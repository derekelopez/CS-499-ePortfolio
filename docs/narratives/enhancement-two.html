Module 4 Milestone 3: Enhancement Two: Algorithms and Data Structure

The artifact I selected for the algorithms and data structures category is my Pirate Intelligent Agent from one of my previous classes. This treasure-hunt project requires an intelligent pirate agent to navigate an 8x8 maze, avoid blocked or invalid moves, and reach the treasure. The original implementation used deep Q-learning (DQN), which combines Q-learning with a neural network. Through interactions with the maze, the agent learns from rewards and penalties, balances exploration and exploitation through an epsilon-greedy strategy, and uses stored experiences during training (Sutton & Barto, 2018).

For the enhancement, I expanded the original project by implementing A* pathfinding as a second solution, improving the maze environment, and refining the data structures supporting the DQN. I chose to retain both approaches because comparing a learned policy with a heuristic search algorithm demonstrates how different computing techniques can solve the same problem with different outcomes. I completed a benchmark using all 50 valid starting positions in the maze. This comparative evaluation is now complete.

I selected this artifact for my ePortfolio because it demonstrates my skills in algorithm design, data structure selection, artificial intelligence, debugging, validation, testing, and performance evaluation. It also demonstrates my ability to improve an existing application without abandoning its original design.

The main algorithmic enhancement was the creation of astar.py. A* prioritizes possible routes through the expression f(n) = g(n) + h(n), where g(n) is the cost accumulated to reach the current position and h(n) estimates the remaining distance to the goal (Hart et al., 1968). I used Manhattan distance as the heuristic because movement in this maze is restricted to horizontal and vertical steps. Python’s heapq module supplies a heap-based priority queue so the search can prioritize positions with smaller estimated total costs (Python Software Foundation, n.d.-b). A set tracks explored positions, while dictionaries store movement costs and predecessor relationships used to reconstruct the path.

The A* implementation records path length, path cost, explored positions, and execution time to support testing. I corrected an incorrectly named result field from pat_length to path_length and fixed an indentation problem that affected searches with default and explicitly supplied goals. These changes improved the consistency of results and the reliability of the algorithm’s interface. I also updated TreasureMaze.py. I corrected state initialization in reset(), added stronger checks for maze dimensions, cell values, and starting positions, and improved the organization of update_state(). In get_reward(), I corrected the order of conditions, so an invalid move is penalized before a visited-position penalty is considered. I also refined valid_actions() to evaluate a supplied position correctly. These are important improvements because inconsistent maze states or rewards can distort both the A* search behavior and DQN learning results. Another enhancement addressed the DQN experience replay structure. I replaced the original list-based memory management with a bounded collections.deque, which automatically discards the oldest entries when it reaches its configured maximum length (Python Software Foundation, n.d.-a). I also strengthened validation when experiences are stored and sampled and reduced unnecessary dependence on global objects. This improvement makes replay-memory management more appropriate for repeated training operations.

I executed both algorithms and evaluated them using the same 50 valid starting positions in the 8x8 maze. The A* algorithm successfully found a path from every position, achieving a 100% success rate. Its average shortest-path length was 15.64 moves, and shortest path reported from (0,0) was 24 moves. A* required no training, and its completion check passed. The DQN was trained for a maximum of 1,000 epochs and then evaluated from those same 50 starting positions. It succeeded once and failed 49 times, fiving it a 2.00% success rate. Its average successful path length was 1.00 move, but this represents only its single success, not a meaningful advantage over A*. Its average evaluation time was 0.563064 seconds per starting position, totaling 28.153212 seconds, and its final epsilon was 0.367695. Its completion check failed.

The DQN average is based on only one successful starting position and is not directly comparable with A* results across 50 successes.

These findings demonstrate that A* was better suited to his observable, deterministic navigation problem under the tested conditions. A* used the known maze layout and heuristic to search systematically for routes. The DQN had not learned a reliable policy after the tested training run. The results do not establish that reinforcement learning is inherently inferior to A*; but, they show why algorithm selection must account for the environment, the available information, and computational requirements (Sutton & Barto, 2018).

The completed comparison also requires careful interpretation. Although the DQN’s only successful path took one move, it failed from 49 other starting positions. Therefore, that one move result cannot be treated as evidence of generally shorter paths. Similarly, the measured DQN evaluation time should not be directly contrasted with an A* runtime unless we have equivalent timing measurements and testing methods are documented for A*.

The trained DQN model was saved as dqn_pirate_agent_1000.keras. The final notebook verification confirmed the presence of the TreasureMaze and GameExperience classes, the DQN model, its qtrain training function, the completion_check function, and DQN evaluation results. One verification item showed ‘A* function: CHECK’ because the check searched the notebook’s global names specifically for astar or a_star. This name check is not the same as an A* benchmark failure; the recorded A* results separately document successful execution across all 50 starting positions.

The enhancement supprts the CS-499 course outcome of designing and evaluating computing solutions using algorithmic principles. I implemented heuristic pathfinding, selected a priority queue and dictionary-based structures appropriate to its operations, improved experience replay with a bounded deque, and conducted a controlled empirical comparison of two approaches. It also supports the application of well-founded computing techniques through modular design, input validation, debugging, and evidence-based evaluation.

One of the most important lessons I learned was that a sophisticated algorithm is not automatically the best algorithm for every task. For a known maze, A* reliably solved all tested positions without a training phase. DQN offers a different model of learning through experience, but in this particular training and evaluation its policy was not reliable. I also learned that successful software enhancement requires more than just adding features: the supporting environment, data structures, tests, and interpretation of results all affect the quality of the final solution.

Overall, the enhanced Pirate Intelligent Agent now includes an operational A* implementation, improved maze and replay-memory logic, executed DQN training and evaluation, and a completed 50-start-position comparison.
