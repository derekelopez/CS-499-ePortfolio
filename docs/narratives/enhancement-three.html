Module 5 Milestone Four: Enhancement Three: Databases

The artifact I selected for the database enhancement is my Smart Thermostat project from a previous computer science class. The original project was created as an embedded system using a Raspberry Pi and Python. It uses an AHT20 temperature and humidity sensor, push buttons, LEDs, a 16x2 LCD display, and serial communication to simulate the operation of a residential thermostat.

The original system monitors environmental conditions, displays the current temperature and thermostat setpoint, and transition between OFF, HEAT, and COOL operating states. Users can increase or decrease the temperature setpoint using physical buttons connected to the system. The original design works well however; it does provide a way to permanently store the environmental data generated by the thermostat.

For the database enhancement, I expanded the thermostat from a primarily local embedded system into a small Internet of Things data system. The enhanced version sends thermostat telemetry from the Raspberry Pi to a Python-based web service, validates the incoming information, and stores the information in a MongoDB database. The stored telemetry includes the temperature, humidity, thermostat setpoint, operating state, and timestamp. I also added database queries and statistical processing that can retrieve readings withing specified time ranges and calculate information such as average temperature, minimum and maximum temperature, average humidity, the number of readings in each thermostat state, and the amount of time spent in each operating state.

I selected the Smart Thermostat for my database enhancement because it allows me to demonstrate how an existing computing system can be expanded through database technology rather than creating an isolated database application. The enhancement demonstrates the relationship between embedded systems, networking, server-side development, validation, persistent storage, and data analysis.

One of the most important improvements was separating the application into multiple responsibilities. The Raspberry Pi continues to perform the thermostat’s primary embedded functions, while a separate service is responsible for receiving and storing telemetry. The server side of the project contains a Flask-based API, a validation layer, and a database-access layer. This separation improves the organization and maintainability of the application because the embedded hardware does not need to communicate directly with MongoDB.

The telemetry API accepts data from the thermostat through the /api/readings endpoint. Before information is stored, the validation component verifies that required fields are present and that values use the expected types of formats. For example, the system validates temperature, humidity, setpoint, thermostat state, and ISO 8601 timestamp information. Thermostat states are restricted to valid values such as OFF, HEAT, and COOL. This prevents invalid or incomplete records from being inserted into the database.

I also developed a database component that manages the connection to MongoDB and inserts validated telemetry records. During testing, I verified that the Flask API could communicate successfully with MongoDB and return the identifier of newly created database documents. I then connected the Raspberry Pi thermostat to the API. The thermostat successfully transmitted real sensor information to the server while continuing to perform its local thermostat operations.

The stored information demonstrates that the system can preserve changing environmental and operating conditions over time. For example, the database successfully recorded temperature and humidity measurements while I transitioned the thermostat between OFF, HEAT, and COOL and adjusted the temperature setpoint. These records provide a historical view of the thermostat rather than only showing its current state.

Another improvement was adding analytical database functionality. I developed a statistics endpoint that can evaluate readings within a specified time period. During testing, one query turned six readings with an average temperature of 82.91 degrees Fahrenheit, a minimum of 82.84 degrees Fahrenheit, a maximum of 82.96 degrees Fahrenheit, and an average humidity of 40.94%. The query also calculated state counts and estimated the amount of time spent in each thermostat operating state. This enhancement demonstrates that the database is not only used for storage, but the stored information can be analyzed.

This enhancement has helped me progress toward several of our Computer Science outcomes. One of the strongest outcomes demonstrated is the ability to use well-founded and innovative computing techniques, skills, and tools to implement solutions that deliver value and accomplish specific goals. The enhanced thermostat combines Raspberry Pi hardware, Python, Flask HTTP communication, MongoDB, database queries, and statistical analysis to create a functional IoT data system.

The project also demonstrates the outcome related to designing and evaluating computing solutions while managing design trade-offs. One important design was to avoid connecting the Raspberry Pi directly to MongoDB. Instead, I created an API layer between the embedded device and the database. This requires more components, but it improves separation of concerns and provides a central location for validation and database access. It also makes it easier to change database implementation later without significantly modifying the embedded thermostat software.

The enhancement also supports the program outcome involving a security mindset. Incoming information is validated before it reaches the database, accepted thermostat states are restricted, and database operations are separated from the embedded device. I also considered keeping credentials and configuration information outside the application logic and designing the system so that database or network failures would not prevent the thermostat from performing its local operation.

The most important lesson I learned during this enhancement was that adding a database to an application involves a lot more than just creating a collection and inserting records. A useful database solution requires careful decisions about where data originate, how it is transported, how it is validated, how it is stored, and how it will be queried.

The enhancement also showed me the importance of modular design. Separating the project into embedded, server, and tests components made it easier to understand which part of the system was responsible for each operation. Within the server component, separating the Flask application, validation logic, and database operations provided improved organization.

I encountered some challenges during development. One of the first happened when the API attempted to store a telemetry record while the MongoDB service was not running. The request failed even though the Flask application was working correctly. After identifying the problem and starting MongoDB service, the same request was successful and stored the telemetry record. This experience showed me the importance of understanding dependencies between services and distinguishing application failures from infrastructure failures.

Connecting Raspberry Pi to the Windows-hosted API also had its challenges. I had a few issues with the telemetry URL and Python imports. The API address needed to contain the correct protocol, port, and /api/ readings route. I also learned that the enhanced thermostat needed to be executed as a Python module so that its relative imports would resolve correctly. Resolving these issues helped me better understand networking, Python package organization, operating-system permissions, and troubleshooting across multiple computers.

Testing the entire system was a great experience. I was able to run the thermostat on Raspberry Pi, experimented with the LCD and LED behavior, change states using the physical buttons, and then confirm that those changes appeared as documents in MongoDB. This proved that the enhancement was working from end to end.

The Smart Thermostat is a great example of how an embedded system can be more complete with a software system. It now includes physical hardware, software architecture, network communication, data validation, persistent storage, queries, and analytical capabilities. The experience helped me observe how database technologies interact with other areas of computer science.
